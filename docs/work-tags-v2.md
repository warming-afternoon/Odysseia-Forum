# 作品标签 V2

## 使用规则

- 一个作品对同一个标准标签只贡献一次使用次数；关联帖子、子卡和来源重复记录不会重复计数。
- Fluxer 作品使用同一套作品标签。历史 Fluxer 概念 ID 保留，界面不再将其作为另一套只读标签。
- 作者或原有管理角色可以直接增删自己有权管理的作品标签，不经过申请。投稿时可选择最多 12 个已有有效标签，所选标签与作品、发布任务在同一事务保存。
- 普通成员继续沿用申请、审核、轮次投票规则；标签分类、别名、互斥和停用规则保持不变。作者权限不等于可以创建、合并或删除全站标签实体。
- 新增深渊标签在投稿、直接挂标和申请入口均校验当前深渊权限；已有标签的纯删除不因失去该权限而被阻止。
- Discord 来源的原生同步规则保持不变。旧 Thread 的本地治理轮次、票数、待审申请和明确标注内部目标编号的审计记录可以从 Work 入口读取。

## 接口

- `POST /v2/works` 新增可选 `tag_ids` 数组，编号建议使用十进制字符串。省略表示不选标签。无效、停用、软删除、超限或互斥标签导致整个创建事务失败，不留下作品或发布任务。
- `GET /v2/tags?q=&offset=0&limit=100` 返回 `items` 与 `has_more`。名称、别名均可检索，候选只包含启用且当前用户可发现的标签；`limit` 最大 200。
- 原有作品作者单标签 PUT/DELETE 接口继续使用；普通成员提案与投票接口保留。
- `GET /v2/works/{work_id}/tag-audit?offset=0` 仅原有管理权限可读，并实时核验身份。返回每页最多 100 项，不改写旧审计事实。
- `POST /v2/tags/stats` 返回 `total_works`、每标签 `total_work_count` 和各频道的 `work_count`，依照作品搜索的内容可见性过滤。统计真实标签按内部 ID 区分，同名不同义概念不会自动合并。虚拟标签继续按名称筛选作品。

## 迁移与部署

在维护窗口停止旧 API、BOT 和任务消费者，备份完整数据库后运行 `work_tag_local_governance`。不能让旧的 Fluxer 标签快照消费者与新版并行写入。

迁移将 Fluxer 作品当前原生挂标转为本地治理轮次。已有生效轮次不重建、不重置票数；多来源同一作品同一标签只导入一次。旧原生来源和绑定记录保留作迁移证据，但新版查询不再把 Fluxer 原生档案视为生效绑定，后续原生标签事件也不覆盖作者操作。不同 ID 的同名概念不自动合并。

迁移后核对当前原生标签均有本地生效轮次，再统一启动新服务。确认 Fluxer 的目标论坛允许不带原生标签创建帖子；作品 TAG 不写入 Fluxer 原生标签字段。需要回滚时使用维护窗口完整备份，不能以删除新轮次的方式覆盖迁移后投票或作者修改。
