# Auditor 模块

Auditor 通过后台轮询补偿 Discord 离线事件，维护帖子、论坛频道资料和原生标签，并清理长期失效的帖子。

## 后台任务

所有任务等待 BOT 连接就绪后执行，卸载 Cog 时取消。

| 任务 | 范围与节奏 |
| --- | --- |
| `channel_audit_loop` | 按独立游标分页审计帖子的频道资料，每次尝试后等待 3 秒，整轮后等待 60 秒 |
| `message_audit_loop` | 按独立游标分页审计帖子消息，每次尝试后等待 0.5 秒，整轮后等待 60 秒 |
| `forum_refresh_loop` | 每轮重新读取已索引频道 ID，逐频道请求完整资料；每次尝试后等待 10 分钟，最后一次等待结束后再等待 3 小时 |
| `cleanup_loop` | 每 6 小时清理 `not_found_count >= 5` 的帖子 |

频道资料刷新复用同一次 HTTP 响应，更新 `channel` 表、论坛内存缓存和原生标签来源。请求使用 API 调度器的后台优先级；数据库会话不跨越 HTTP 请求和休眠。

`forum_refresh_loop` 统一刷新频道资料和原生标签。在线的频道更新事件即时同步，离线标签变化由慢速轮询补偿。

单频道失败后保留旧资料，照常等待 10 分钟并处理后续频道；列表读取失败或列表为空时等待 3 小时。取消任务时立即传播取消异常，不再开始下一频道。

## 频道资料持久化

`channel` 表同时保存论坛频道和 Banner 使用的赛事文字频道。`guild_name`、`category_name`、`channel_type`、`synced_at` 分别保存服务器名称、分类名称、频道类型和资料采集时间；这些字段允许为空，未知信息由 BOT 同步补齐。`channel_type` 使用 Discord 原生整数，论坛为 `15`、文字频道为 `0`。

论坛目录仅包含已索引的论坛频道，不将 Banner 单独入库的文字频道加入目录。BOT 启动构建缓存、首次网关就绪、重新索引及手动重建缓存时更新数据库；频道名称、简介、分类、标签及服务器/分类改名事件也会刷新资料。

频道和可信原生标签快照在同一事务提交，快照时间记录采集开始时的 UTC 时间，防止晚返回的旧响应覆盖新资料。缓存重建不会把未变化的本地资料伪装成新观测。

原生标签使用现有来源表保存，API 独立从数据库构建论坛目录并定时刷新，无需 BOT 发布 Redis 快照。`synced_at` 表示频道资料观测时间，标签完整同步进度由 `discord_tag_sync_state` 表记录。
